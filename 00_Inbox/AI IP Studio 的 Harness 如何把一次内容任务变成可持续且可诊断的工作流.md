# AI IP Studio 的 Harness 如何把一次内容任务变成可持续且可诊断的工作流？

## 为什么会问这个问题？

项目的成功标准不是只画出 AI Harness 架构，而是让 AI IP Studio 能开始真实工作，并且当结果或运行过程出错时，用户能定位问题所在的层。

暂时使用一个最小但真实的诊断场景：根据已有世界观资料，产出一篇不违背正史的短篇故事。它用于暴露端到端链路，不限制未来小说、游戏和跨媒介生产的范围。

---

## 第一次闭卷回答

> Model相当于是agent的大脑，而Agent相当于是一个职位，它用Model来思考，他自己的身份比如说写手，它负责的任务就是写作内容，Skill相当于是它写作时候采用的手法，Tool的意思是用哪些方法来写，就比如用铅笔还是钢笔，但是这里是调用了方法，MCP的意思是，比如我要用typora来写，我就得知道我和typora之间的数据传输协议是什么，二者怎么进行数据沟通，Session就是我们这次具体行动，产生了什么样的对话，而Workflow的意思是，我这个agent先写，然后你那个agent负责审核，另一个agent负责比较和过去的历史，是否出现了错误，所有所有的这一切，就叫做Harness

## 我卡住的地方

- 已能用职位分工类比说明各组成部分，但还没有说明一次任务中的数据如何在各层之间流动。
- 已开始按照 Tool、Skill、Workflow、Session 分层排查，但把“故障发生的组件”和“保存排查证据的位置”混在了一起。
- 还没有说出要查看的具体记录及其预期内容，因此暂时无法用证据排除某一层。
- `Session` 目前主要被当作审核 Workflow 的排查对象，尚未说明它在复现与诊断中的记录作用。
- `Harness` 目前解释为“所有这一切”，尚未说明它怎样让这些部分形成可控制、可追踪、可恢复的系统。

## Codex 费曼追问

### 第一轮

如果现在不看资料，要让 AI IP Studio 根据已有世界观产出一篇不违背正史的短篇故事，你会怎样解释它从任务输入到最终交付的完整链路？请在解释中自然说明 Model、Agent、Skill、Tool、MCP、Session、Workflow、Harness 各负责什么，以及哪里保存了以后定位问题所需的证据。

### 第二轮

1. 写手 Agent 交付的故事把角色出生地写错了。你会查看哪些实际记录，才能区分：写手从未拿到正确设定、拿到了但 Model 没遵守、外部资料读取失败，还是审核 Workflow 漏掉了错误？
2. 为了让你半年后仍能复现这次错误，`Session` 除了对话以外还必须保存什么？请说出你认为最重要的内容，不需要使用标准术语。

### 第三轮

现在 Session 中已经能看到下面四条记录：

1. 写手 Agent 请求查询角色甲的出生地。
2. Tool/MCP 返回的原始结果明确写着“出生地：北港”。
3. 写手收到这条结果后，在故事中写成了“南城”。
4. 审核 Agent 确实被 Workflow 调用，也同时收到了原始设定和故事，但最终返回“审核通过”。

只根据这些证据回答：哪些层可以确定没有失败，哪些层可以确定出现了失败，哪些层仍然不能下结论？说明每个判断依据的是哪条记录。

### 第二轮回答

> 写手没有拿到正确设定，那么意思是写手可能读取设定失败，或者读取了错误的设定，读取设定失败，需要去排查是否是，tool的部分出现了错误导致读取到了错误的设定，model拿到了但是没有遵守，需要检查skill的设置是否合理正确，审核workflow是否出了错误，需要检查session的部分
